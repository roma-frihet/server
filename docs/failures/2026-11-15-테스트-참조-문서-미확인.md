# 테스트 규칙 문서를 읽지 않고 테스트를 작성

- 요약: 과목과 반 번호 기능의 테스트 16개를 쓰면서 그중 9개를 `@SpringBootTest` + Testcontainers로 만들었다. `없는 과목으로는 수업을 만들 수 없다`처럼 서비스 로직만 보면 되는 것까지 앱 컨텍스트 전체와 Postgres 컨테이너를 띄워 확인했다. 테스트 메서드 순서도 3개 클래스에서 어긋났다. 사용자가 "의존성 관련해서 잘 만들어진 테스트는 맞는거야?"라고 물어 발견했다.
- 원인: `spring-kotlin` 스킬의 `SKILL.md`에 "테스트를 작성할 때는 `references/testing.md`를 함께 읽습니다"라고 적혀 있는데 읽지 않았다. 스킬 본문만 보고 참조 문서를 건너뛰었다. 그 문서에 범위 선택 표("가장 좁은 범위로 시작합니다")와 순서 규칙("정상 경로, 다른 경로와 경계값, 오류 순")이 있었다. 프로젝트에 이미 `ClassroomServiceTest`라는 MockK 단위 테스트 선례가 있었는데 그것도 열어 보지 않았다.
- 재발 방지: 넓은 범위 테스트 2개 클래스를 지우고 서비스(MockK), 레포지토리(`@DataJpaTest`), 컨트롤러(`@WebMvcTest`)로 나눠 다시 만들었다. 메서드 순서도 규칙대로 정렬했다. 나누는 과정에서 `@DataJpaTest`가 `JpaConfig`를 안 올려 컨텍스트가 뜨지 않는 문제와, `save`를 스텁하면 id가 null이라 `requireNotNull`에서 터지는 문제가 드러났다. 넓은 범위 테스트였으면 둘 다 가려졌을 결함이다. 앞으로 테스트를 쓰기 전에 스킬이 지정한 참조 문서를 먼저 연다.
- 강제 수단: 문서만. 같은 실수가 한 번 더 나오면 ArchUnit으로 올린다 — `@SpringBootTest`를 붙인 테스트 클래스 수에 상한을 두는 방식이 가능하다.
