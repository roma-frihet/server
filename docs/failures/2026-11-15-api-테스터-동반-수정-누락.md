# API를 바꾸고 테스터를 고치지 않음

- 요약: 교사 도메인을 개편하면서 수업 생성(`subject` → `subjectId`), 반 생성(`name` → `classNo`), 합류 승인 제거, 문제 제한 시간·해설까지 API를 대거 바꿨는데 `tools/api-tester/`와 README의 테스터 설명을 그대로 두었다. 테스터는 없어진 `approve`, `reject`, `approve-all`을 계속 호출하고 지워진 `classroomName`, `subject`, `status` 필드를 읽는 상태였다. 사용자가 "프론트 전달용 API 목록도 기존에 쓰고 있었던거면 그거 당연히 수정해야지"라고 지적해 발견했다.
- 원인: `CLAUDE.md`에 "API 경로나 Request, Response를 바꾸면 `tools/api-tester/`와 README의 API 테스터 설명도 함께 고칩니다. `check`로 잡히지 않습니다"라는 규칙이 이미 있었다. 읽고도 작업 중에 떠올리지 못했다. `./gradlew check`가 계속 초록불이라 빠진 걸 눈치채지 못한 것이 컸다. 규칙이 바로 그 상황을 경고하고 있었는데 초록불을 완료 신호로 받아들였다.
- 재발 방지: 테스터의 호출 경로와 필드를 새 API에 맞췄고, README의 테스트 순서 표에서 3분→5분, 승인 단계 제거, 과목 선택과 제한 시간을 고쳤다. 앞으로 rqrs나 Controller 경로를 건드린 턴에는 `tools/api-tester/index.html`을 반드시 함께 연다.
- 강제 수단: 문서만. `check`로는 잡히지 않는다. 같은 실수가 한 번 더 나오면 훅으로 올린다 — `src/main/kotlin/**/rqrs/**` 또는 `**/*Controller.kt`가 바뀐 커밋에서 `tools/api-tester/index.html`이 함께 바뀌지 않으면 경고하는 방식이 가능하다.
