# 독립 기능을 다른 기능 패키지 안에 넣음

- 요약: 과목을 교육과정 목록으로 바꾸면서 `Subject` 엔티티, `SubjectRepository`, `SubjectService`, `SubjectTeacherController`, `SubjectDto`, `SubjectResponse`를 전부 `course/` 패키지 안에 만들었다. 한 기능에 필요한 클래스가 다 모여 있는데도 독립 패키지를 주지 않았다. 사용자가 "지금 패키지 구조를 잘 따르게 설계한거야?"라고 물어 발견했다.
- 원인: `Course`가 `Subject`를 참조하니 같은 패키지에 두는 게 자연스럽다고 판단했다. `CLAUDE.md`의 "패키지는 레이어가 아니라 기능별로 나눕니다"를 참조 관계로 착각했다. 바로 옆에 `school/`이라는 선례가 있었다 — 마이그레이션으로 시드하는 참조 데이터이고, 자기 Controller·Service·Repository·Entity를 가지며, `course`와 `teacher`가 참조한다. 성격이 똑같은데 `school`은 독립 패키지를 받았고 `subject`만 못 받았다. 작업 전에 비슷한 기존 코드를 열어 보라는 규칙도 지키지 않았다.
- 재발 방지: `subject/` 패키지로 옮겼다. 의존은 `course → subject` 단방향이고 순환은 없다. 앞으로 Controller·Service·Repository·Entity가 함께 생기면 그 자체로 독립 기능이므로 패키지를 따로 만든다.
- 강제 수단: 문서만. ArchUnit의 순환 검사는 이 경우를 잡지 못한다. 순환이 아니라 배치 문제이기 때문이다. 같은 실수가 한 번 더 나오면 "한 패키지에 서로 다른 접두어의 Controller가 둘 이상 있으면 실패"하는 ArchUnit 규칙으로 올린다.
- 근거: `CLAUDE.md`의 `구조` 절, `src/main/kotlin/com/romafrihet/server/school/`, `src/main/kotlin/com/romafrihet/server/subject/`
